# ellmer upstream feature surface

Checked 2026-08-21 against official ellmer docs and the tidyverse/ellmer GitHub repository/source. This note is meant to compare upstream ellmer with the local `ellmercodex` repo without changing code.

## Executive finding

Upstream `ellmer` is much broader than the local Codex-focused wrapper. The current public surface is centered on a provider-agnostic `Chat` object, many provider/model factories, rich tool and structured-data APIs, multimodal content helpers, async and parallel/batch execution, provider-specific caching and reasoning controls, and observability hooks. The local repo currently exposes only the Codex-specific entry points (`chat_codex()`, `codex_login()`, `codex_logout()`, `codex_account()`, `codex_available()`, `codex_models()`) and relies on ellmer internally for the chat object and message/tool machinery.

## Evidence matrix

| Area | Upstream surface | What that means for `ellmercodex` |
| --- | --- | --- |
| Core chat model | `chat()` is the generic provider selector, and the `Chat` R6 object owns turn history, model/system-prompt updates, token/cost accounting, `chat()`, `chat_structured()`, `chat_async()`, `stream()`, `stream_async()`, tool registration, and tool callbacks. [Package index](https://ellmer.tidyverse.org/reference/index.html) [Chat](https://ellmer.tidyverse.org/reference/Chat.html) [chat()](https://ellmer.tidyverse.org/reference/chat-any.html) | The local repo exposes a single `chat_codex()` wrapper instead of the full provider selector. |
| Providers and models | The package index lists many official and community providers, with matching `chat_*()` and `models_*()` factories, including OpenAI, Anthropic/Claude, AWS Bedrock, Azure OpenAI, Databricks, DeepSeek, GitHub model marketplace, Google Gemini/Vertex, Ollama, Posit AI, Snowflake, Cloudflare, Groq, Hugging Face, LM Studio, Mistral, OpenRouter, Perplexity, Portkey, and vLLM. [Package index](https://ellmer.tidyverse.org/reference/index.html) [ellmer GitHub README](https://github.com/tidyverse/ellmer) | The local repo currently targets Codex only, so upstream provider breadth is not present here. |
| OpenAI / OpenAI-compatible | `chat_openai()` now uses the Responses API and documents image generation and web search; `chat_openai_compatible()` covers chat-completions-style or other OpenAI-compatible endpoints. [chat_openai](https://ellmer.tidyverse.org/reference/chat_openai.html) [chat_openai_compatible](https://ellmer.tidyverse.org/reference/chat_openai_compatible.html) [provider-openai source](https://github.com/tidyverse/ellmer/blob/main/R/provider-openai.R) | The local repo’s transport is an experimental Codex-specific compatibility path, not a general OpenAI-compatible provider layer. |
| Authentication and config | Provider docs show a mix of API keys, credential callbacks, ambient cloud credentials, service principals, viewer-based credentials, and interactive OAuth fallbacks, plus provider-specific config such as `service_tier`, `api_args`, `api_headers`, `beta_headers`, and `preserve_thinking`. [Provider](https://ellmer.tidyverse.org/reference/Provider.html) [chat_openai](https://ellmer.tidyverse.org/reference/chat_openai.html) [chat_azure_openai](https://ellmer.tidyverse.org/reference/chat_azure_openai.html) [chat_google_gemini](https://ellmer.tidyverse.org/reference/chat_google_gemini.html) [chat_anthropic](https://ellmer.tidyverse.org/reference/chat_anthropic.html) | `ellmercodex` uses its own browser sign-in and package-scoped credential storage; it does not expose upstream’s provider-agnostic credential model. |
| Tools and function calling | `tool()`, `tool_annotations()`, `tool_reject()`, `type_*()` schemas, `create_tool_def()`, registered tool callbacks, and content-rich tool request/result objects are all part of the public API. [tool](https://ellmer.tidyverse.org/reference/tool.html) [tool_annotations](https://ellmer.tidyverse.org/reference/tool_annotations.html) [Type](https://ellmer.tidyverse.org/reference/Type.html) [Content](https://ellmer.tidyverse.org/reference/Content.html) [create_tool_def](https://ellmer.tidyverse.org/reference/create_tool_def.html) [Chat](https://ellmer.tidyverse.org/reference/Chat.html) | The local repo implements Codex tool looping on top of ellmer, but not a new tool-definition system of its own. |
| Structured data | `Chat$chat_structured()` and `Chat$chat_structured_async()` are first-class, and `parallel_chat_structured()` / `batch_chat_structured()` exist for multi-prompt extraction. [Chat](https://ellmer.tidyverse.org/reference/Chat.html) [structured-data article](https://ellmer.tidyverse.org/articles/structured-data.html) [parallel_chat](https://ellmer.tidyverse.org/reference/parallel_chat.html) [batch_chat](https://ellmer.tidyverse.org/reference/batch_chat.html) | The local repo’s structured-output support is narrower and is implemented as a Codex transport compatibility layer. |
| Streaming and multimodal content | `Chat$stream()` / `Chat$stream_async()` can emit either text or rich content; ellmer also exposes `content_image_*()` and `content_pdf_*()` helpers. The content model includes text, images, tool requests/results, PDFs, and thinking content. [Chat](https://ellmer.tidyverse.org/reference/Chat.html) [Content](https://ellmer.tidyverse.org/reference/Content.html) [content_image_url](https://ellmer.tidyverse.org/reference/content_image_url.html) [content_pdf_file](https://ellmer.tidyverse.org/reference/content_pdf_file.html) | The local repo supports multimodal turns through ellmer, but only within the Codex-focused chat wrapper. |
| Async and concurrency | `Chat$chat_async()`, `Chat$stream_async()`, `parallel_chat()`, `parallel_chat_text()`, `parallel_chat_structured()`, `batch_chat()`, `batch_chat_text()`, `batch_chat_structured()`, and `batch_chat_completed()` are public. Parallel chat supports `max_active`, `rpm`, and `on_error`; batch chat persists state to a JSON file and can be resumed. [Chat](https://ellmer.tidyverse.org/reference/Chat.html) [parallel_chat](https://ellmer.tidyverse.org/reference/parallel_chat.html) [batch_chat](https://ellmer.tidyverse.org/reference/batch_chat.html) | The local repo covers async chat/streaming on the Codex chat object, but not the broader parallel/batch APIs. |
| Caching | ellmer reports `cached_input` in token accounting, exposes provider-level prompt caching for Claude and AWS Bedrock, and batch jobs can be stored/resumed from a state file. [token_usage](https://ellmer.tidyverse.org/reference/token_usage.html) [chat_anthropic](https://ellmer.tidyverse.org/reference/chat_anthropic.html) [chat_aws_bedrock](https://ellmer.tidyverse.org/reference/chat_aws_bedrock.html) [batch_chat](https://ellmer.tidyverse.org/reference/batch_chat.html) | The local repo does not surface equivalent generic cache controls; any caching it has is transport-specific. |
| Logging and observability | ellmer 0.4.1 is instrumented with OpenTelemetry when the suggested `otel` package is present; chat, async, stream, and tool spans are emitted, and tool callbacks can be used for custom logging. [GitHub releases](https://github.com/tidyverse/ellmer/releases) [Chat](https://ellmer.tidyverse.org/reference/Chat.html) | The local repo has its own redacted diagnostics, but it does not expose upstream’s OTEL-backed observability surface. |
| Interactive and console tooling | `live_console()` and `live_browser()` provide interactive chat UIs, and the top-level `chat()` generic lets you select a provider/model by string. [live_console](https://ellmer.tidyverse.org/reference/live_console.html) [chat()](https://ellmer.tidyverse.org/reference/chat-any.html) | The local repo is not a general interactive chat shell; it is a package API around Codex sign-in and chat. |
| Batch and cost reporting | `token_usage()` reports input/output/cached-input tokens and cost; `Chat$get_tokens()` and `Chat$get_cost()` expose per-chat accounting. [token_usage](https://ellmer.tidyverse.org/reference/token_usage.html) [Chat](https://ellmer.tidyverse.org/reference/Chat.html) | The local repo tracks only the Codex-facing subset needed for its wrapper. |
| Built-in integrations | Current docs mention built-in web search/fetch tools for OpenAI, Google Gemini, and Claude, plus provider-specific helpers such as `google_upload()`. [GitHub releases](https://github.com/tidyverse/ellmer/releases) [Package index](https://ellmer.tidyverse.org/reference/index.html) [chat_google_gemini](https://ellmer.tidyverse.org/reference/chat_google_gemini.html) [chat_openai](https://ellmer.tidyverse.org/reference/chat_openai.html) | These integrations are upstream features; the local repo does not add them as new public APIs. |

## Local repo comparison

From the local `NAMESPACE` and package docs, the exported surface is intentionally small:

- `chat_codex()`
- `codex_login()`
- `codex_logout()`
- `codex_account()`
- `codex_available()`
- `codex_models()`

See [NAMESPACE](/Users/simonherrera/Documents/git/ellmercodex/NAMESPACE) and [README.md](/Users/simonherrera/Documents/git/ellmercodex/README.md).

That means the fork already has a useful Codex wrapper, but it is missing most of upstream ellmer’s general-purpose surface area: provider selection, live console/browser, parallel and batch helpers, public tool-definition helpers, provider-level caching knobs, and the upstream observability story.
